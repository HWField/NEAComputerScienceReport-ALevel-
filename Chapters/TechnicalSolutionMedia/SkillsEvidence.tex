\section{Coding Style}

In addition to the techniques listed above, I have also adhered to best practices in coding style and maintainability. This includes consistent naming conventions, modular code organization, comprehensive commenting, and adherence to SOLID principles in object-oriented design. These practices ensure that my code is not only functional but also readable and maintainable for future developers who may work on this project.

The SOLID principles applied throughout the project are outlined below:
\begin{itemize}
    \item \textbf{Single Responsibility Principle (SRP):} Each class and module is designed to have a single, well-defined responsibility. This reduces complexity and makes the code easier to understand, test, and modify.
    \item \textbf{Open/Closed Principle (OCP):} Classes are open for extension but closed for modification. New functionality can be added through new classes or methods without altering existing, tested code.
    \item \textbf{Liskov Substitution Principle (LSP):} Subclasses can be used interchangeably with their parent classes without affecting program correctness, ensuring predictable behaviour when using inheritance.
    \item \textbf{Interface Segregation Principle (ISP):} Interfaces are kept small and focused so that classes only implement methods they actually require, avoiding unnecessary dependencies.
    \item \textbf{Dependency Inversion Principle (DIP):} High-level components depend on abstractions rather than concrete implementations, improving flexibility and making the system easier to test and maintain.
\end{itemize}

This table serves to highlight not only the techniques I have implemented but also the underlying design philosophies that guided my development process.
